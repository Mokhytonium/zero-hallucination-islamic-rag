# تصمیم‌های داده‌محور (فاز قرآن)

> این تصمیم‌ها بر اساس **دیتابیس واقعی آپلودشده** (`data/raw/quran/`) گرفته شده‌اند، نه فرض.
> سند مرجع معماری: [`architecture.md`](architecture.md) · پروپوزال: [`../code_artifact.md`](../code_artifact.md)

## داده‌ی ورودی چه بود

دامپ MySQL شامل جدول‌های `quran_text` (اعراب‌دار + صفحه/جزء/حزب)، `quran_clean_text` (بدون اعراب)، `quran_text2` (تکراری)، `suras` (۱۱۴ سوره با مکی/مدنی و ترتیب نزول)، `suretranslate` (ترجمه‌ی فارسی با مترجم نامشخص) و `estekhare` (نامرتبط). پوشه‌ی `trns` ترجمه‌های Tanzil.net است: چهار ترجمه‌ی فارسی (انصاریان، آیتی، بهرام‌پور، مکارم) و ~۳۰ زبان دیگر.

## طرح‌واره‌ی ذخیره‌سازی

`sources` (provenance) · `surahs` · `records` (متن نمایشی/ایندکس + متادیتای JSON) · `translations` · `vectors` (نسخه‌دار per مدل) · `records_fts`/`translations_fts` (FTS5) · `cache` · `api_usage` (هزینه‌سنج).

طرح‌واره source-agnostic است تا نهج‌البلاغه و الکافی بدون migration اضافه شوند.

## تریگرهای مهاجرت به Postgres+pgvector / Qdrant

استقرار چندنفره‌ی سروری · عبور از ~۱۰۰٬۰۰۰ قطعه · نیاز به نوشتن هم‌زمان. تا آن زمان SQLite کافی است و لایه‌ی repository تعویض engine را ایزوله می‌کند.

## راستی‌آزمایی انجام‌شده

- ۶۲۳۶ آیه، ۱۱۴ سوره، ۴×۶۲۳۶ ترجمه، FTS پر شده.
