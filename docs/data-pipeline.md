## منابع داده

| منبع | ماهیت | نکات کلیدی |
|------|-------|-----------|
| **قرآن کریم** | متن وحیانی + ترجمه | نیازمند بانک خلاصه‌ی شأن نزول هر آیه |
| **نهج‌البلاغه** | خطبه‌ها، نامه‌ها، حکمت‌ها | شکستن متون بلند به قطعات موضوعی؛ حفظ مخاطب و فضای صدور |
| **الکافی** | اصول، فروع، روضه (~۱۶٬۰۰۰ حدیث) | تفکیک سند از متن؛ الحاق برچسب اعتبار سندی |

## ۱. پیش‌پردازش و نرمال‌سازی

هدف: یکسان‌سازی نویسه‌های عربی/فارسی و پاک‌سازی علائم اضافی، هم در متن و هم در ترجمه، به‌گونه‌ای که بردار و ایندکس واژگانی هر دو از آن بهره ببرند.

قواعد نرمال‌سازی **پیاده‌سازی‌شده** (`normalize.py`، با آزمون واحد):

- **یکسان‌سازی نویسه‌ها:** أ إ آ ٱ → ا، ى ی → ي، ک → ك، ة → ه.
- **اعراب (تشکیل):** در نسخه‌ی *ایندکس* کاملاً حذف می‌شود (بازه‌های ۰۶۴B–۰۶۵F، ۰۶۷۰، ۰۶D6–۰۶ED، ۰۸F0–۰۸F3 و کشیده‌ی ۰۶۴۰)؛ متن نمایشی همیشه اعراب‌دار و دست‌نخورده از دیتابیس خوانده می‌شود.
- **نویسه‌های کنترلی:** ZWNJ به فاصله تبدیل و نویسه‌های جهت‌دهی/نامرئی (ALM، LRM، RLM، ZWJ، BOM) حذف می‌شوند.
- **اعداد:** ارقام عربی/فارسی به لاتین یکسان می‌شوند.
- **فاصله‌ها:** همه‌ی فاصله‌های تکراری به یک فاصله‌ی ساده تبدیل می‌شوند.
- **بسم‌الله:** در نسخه‌ی ایندکس، بسم‌الله ابتدای آیات اول سوره‌ها (جز فاتحه و توبه) حذف می‌شود تا بردار/FTS تحت‌اللفظیِ «بسم الله» همه‌ی سوره‌ها را برنگرداند؛ متن نمایشی دست‌نخورده می‌ماند.
- **ذخیره‌ی متن نسخه‌ی اصل:** نسخه‌ی «خام و دست‌نخورده» (`text_display`) برای نمایش حفظ می‌شود؛ نرمال‌سازی فقط روی نسخه‌ی ایندکس (`text_index`) اعمال می‌گردد.

## ۲. جداسازی سند از متن حدیث

مسئله: در الکافی، سلسله‌ی راویان (مانند *«عدة من أصحابنا عن أحمد بن محمد...»*) اگر همراه متن در مدل امبدینگ وارد شود، بردار ریاضی دچار نویز می‌گردد.

راه‌حل: در فاز آفلاین، سلسله‌ی راویان از متن اصلی **جدا** شده و در بخش متادیتا ذخیره می‌شود؛ مدل امبدینگ فقط معنای خالص کلام معصوم را بردارسازی می‌کند.

اجزای یک رکورد حدیث پس از تفکیک:

- `matn` — متن خالص حدیث (ورودی امبدینگ)
- `isnad` — سلسله‌ی راویان (فقط متادیتا)
- `authenticity_weight` — امتیاز اعتبار سندی (فقط متادیتا، برای رتبه‌بندی)

## ۳. قطعه‌بندی هوشمند و بافت تاریخی

### قرآن کریم

- هر آیه به‌عنوان یک واحد مستقل امبد می‌شود.
- برای جلوگیری از قطع شدن سیاق، **آیه‌ی قبل، آیه‌ی بعد و خلاصه‌ی شأن نزول** در «شناسنامه»ی همان آیه پیوست می‌گردد.

> **تصمیم نهایی (پیاده‌سازی شده):** فقط متن *خالص* آیه (`text_index` نرمال‌شده) امبد می‌شود؛ آیه‌ی قبل/بعد با `prev_id`/`next_id` در دیتابیس می‌مانند و هنگام واکشی به‌صورت بایت‌دقیق به خروجی اضافه می‌شوند — بردار آیه با معنای همسایه‌ها رقیق نمی‌شود. داده‌ی شأن نزول در منبع Tanzil وجود ندارد (`null`) و limitation صادقانه‌ی سامانه است.

### نهج‌البلاغه

- حکمت‌ها به‌صورت کامل امبد می‌شوند.
- خطبه‌ها و نامه‌های طولانی به **قطعات موضوعی مستقل** (پاراگراف‌های معنایی) تقسیم می‌شوند.
- نام مخاطب (مثلاً مالک اشتر یا عثمان بن حنیف) و فضای تاریخی صدور به هر قطعه الصاق می‌گردد.

### الکافی

- هر حدیث کامل یک واحد مستقل است.
- عنوان «کتاب»، «باب» و «درجه‌ی اعتبار سندی» به‌عنوان اطلاعات تکمیلی ثبت می‌شود.

## ۴. طرح‌واره متادیتا

**طرح‌واره‌ی پیاده‌سازی‌شده‌ی قرآن** (جدول `records` + `translations` + `vectors`):

```jsonc
// رکورد آیه (records)
{
  "id": "quran:2:255",
  "source": "quran",
  "sura": 2,
  "aya": 255,
  "text_display": "اللَّهُ لَا إِلَٰهَ إِلَّا هُوَ ...",  // اعراب‌دار، برای نمایش
  "text_index": "...",                  // نرمال‌شده، برای FTS5 و امبدینگ
  "page": 42,
  "juz": 3,
  "hizb": 9,
  "prev_id": "quran:2:254",
  "next_id": "quran:2:256",
  "metadata": {
    "surah_name": "البقرة",
    "revelation_place": "Medinan",      // Meccan | Medinan
    "revelation_order": 87,
    "sha_nuzul": null,                  // در منبع Tanzil وجود ندارد
    "sha_nuzul_source": null
  }
}
// ترجمه‌ها در جدول جدا با کلید translator_id (مثلاً fa.makarem)
// بردارها در جدول vectors با کلید (record_id, kind, model) — نسخه‌دار per مدل
```

نمونه‌های زیر برای **فازهای آتی** (نهج‌البلاغه و الکافی) پیشنهادی هستند؛ طرح‌واره‌ی `records` منبع-agnostic است و بدون migration گسترش می‌یابد:

```jsonc
// نهج‌البلاغه
{
  "id": "nahj:sermon:27:chunk:2",
  "source": "nahj",
  "kind": "sermon",          // sermon | letter | wisdom
  "number": 27,
  "chunk_index": 2,
  "addressee": "...",
  "historical_context": "...",
  "text_ar": "...",
  "translation_fa": "..."
}
```

```jsonc
// الکافی
{
  "id": "kafi:usul:book1:chapter3:h12",
  "source": "kafi",
  "section": "usul",         // usul | furu | rawda
  "book": 1,
  "chapter": 3,
  "hadith_no": 12,
  "isnad": "عدة من أصحابنا عن أحمد بن محمد ...",
  "matn": "...",
  "translation_fa": "...",
  "authenticity_weight": 0.9
}
```

## ۵. بردارسازی و ایندکس ترکیبی

- **Dense:** متن خالص نرمال‌شده (`text_index`) هر قطعه با `BAAI/bge-m3` محلی به بردار ۱۰۲۴بعدی تبدیل می‌شود؛ برای آیات دو بردار عربی/فارسی (از ترجمه‌ی اصلی) ساخته می‌شود.
- **Sparse (قطعی):** `SQLite FTS5` با رتبه‌بندی BM25 روی متن عربی و ترجمه‌ها؛ توکن‌سازی با نرمال‌سازی اختصاصی و حذف stopwords. **ریشه‌یاب عربی استفاده نشد** و هیچ LLM‌ای در ایندکس واژگانی دخیل نیست — فرض «مصرف توکن صفر در بازیابی» حفظ شده است.

## ۶. ذخیره‌سازی و سهمیه‌ی منابع

**پیاده‌سازی فعلی:** یک دیتابیس `SQLite` با طرح‌واره‌ی منبع-agnostic (ستون `source` در `records`)؛ قرآن به‌تنهایی بارگذاری شده است.

طرح اصلی، **سهمیه‌ی مستقل جست‌وجو برای هر منبع** است تا حجم بالای روایات الکافی باعث نشود آیات قرآن یا کلام نهج‌البلاغه در نتایج به حاشیه بروند. با اضافه‌شدن منابع جدید، بازیابی موازی per-source با سهمیه‌ی جداگانه پیاده‌سازی می‌شود؛ طرح‌واره‌ی فعلی بدون migration گسترش می‌یابد.
